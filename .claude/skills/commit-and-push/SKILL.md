# 커밋/푸시/PR 위임

이 스킬은 git 작업을 `.claude/agents/git-ops.md`에 정의된 `git-ops` 에이전트에게 위임하는 고정 절차다.

## 절차

1. 먼저 변경이 검증됐는지 확인한다 — 아직 lint/build/test를 실행하지 않았다면 `git-ops`에게 위임하기 전에 사용자에게 알리거나, 에이전트 프롬프트에 "커밋 전에 변경된 workspace의 build/test를 재실행해서 통과를 확인할 것"을 명시한다.
2. 요청 범위를 구분한다:
   - **커밋만**: `git-ops` 에이전트에게 "커밋까지만 수행, push는 하지 말 것"을 명시해서 위임한다.
   - **커밋+push**: 어느 브랜치로 push할지 확인한다(현재 브랜치 유지가 기본). main/master로의 직접 push는 피하고 feature 브랜치를 쓰도록 지시한다.
   - **PR 생성까지**: push 이후 `gh pr create`로 PR을 만들도록 지시한다. base 브랜치, 저장소 URL이 이미 알려져 있으면 프롬프트에 포함한다.
3. `git-ops` 에이전트를 호출한다. 프롬프트에는 범위(커밋만/커밋+push/PR까지), 대상 브랜치, 알려진 저장소 정보를 명시한다.
4. push나 PR 생성처럼 되돌리기 어렵거나 공유 상태에 영향을 주는 단계는, 에이전트가 실행 직전 사용자 확인을 받도록 프롬프트에 명시한다 — 이미 한 번 승인받은 범위를 벗어나는 추가 push/force 동작은 별도로 다시 확인받아야 한다.
5. 에이전트 결과(커밋 해시, 브랜치, PR URL)를 사용자에게 그대로 전달한다.

## 주의

- git/PR 관련 블로커(예: 서로 공통 히스토리가 없는 브랜치)가 생기면, 해결 방법을 임의로 선택해 실행하지 않고 옵션을 제시해 사용자의 선택을 받는다.
